## Unreleased

### Breaking

- **Neutral app terminology — hard rename, no compatibility aliases.** The game-shaped API surface is renamed across engine, CLI, config, and docs; games remain a supported app genre, but the platform no longer assumes them. ### Added

- **Damage-driven rendering — `AppRendererConfig.damageOnly`** — when enabled, `renderFrame()` skips the entire GPU block (surface acquire, pass encoding, submit, present) on ticks where nothing reported damage, so UI-style apps idle at ~0 render cost instead of compositing the same frame at display refresh (360Hz panels burned ~half a core). While skipped ticks continue, the loop also **disarms rAF and parks on a low-rate keepalive timer** (`damageIdleFps`, default 20Hz; `0` = sleep fully) — the platform's rAF wait is what keeps the native event pump hot at frame cadence, so disarming lets it drop to its deep-sleep backoff (~62 iterations/s vs ~500). Frame hooks still run on every keepalive tick — they are the damage producers — so periodic producers keep working at the reduced rate. Damage sources re-arm the chain immediately via `requestFrame()`: `ScreenUiCompositor.takeDirty()` + html-ui's `onDamage` wake (every panel frame upload / rect / mount / unmount; devtools `TextSurface` exposes its internal flag), pointer/wheel/key events on the surface, resize, worker `postPass` arrivals (`GpuPassMailbox.onPush`), device recovery, `renderOnce()` (screenshots/deterministic steps always force a frame), and explicit `renderer.requestFrame()` / `ctx.requestFrame()` calls. Compositors without `takeDirty()` are treated as always-dirty, so the gate can never starve an unported compositor. Warmup: ~8 frames render unconditionally after enable/boot/device-recovery so late-binding producers settle. `renderer.setDamageOnly(bool)` toggles at runtime.
- **GPU adapter policy + automatic software fallback** (`platform-native/src/gpu/adapter-policy.ts`, `adapter-boot.ts`) — the native host's adapter/device acquisition is now policy-driven instead of a raw `requestAdapter` call. Some virtualization drivers (Mesa **Venus** on virtio-gpu, Android-emulator **gfxstream**) `abort()` the process inside `requestDevice` rather than returning an error, so the policy rejects denied adapters after the info query but before device creation, then retries on wgpu's software fallback adapter (llvmpipe/lavapipe). `softwareFallback` defaults to **on** — apps get reliable software rendering for free.
- **`downdraft.config.json` `"gpu"` block** — per-app GPU settings, the settings-file half of the toggle: `{ "gpu": { "mode": "performance"|"stability", "adapter": "auto"|"hardware"|"software", "backend": "auto"|"vulkan"|"gl"|"metal"|"dx12", "softwareFallback": bool, "glFallback": bool, "deny": [substrings] } }`.
- **`gpu.mode` preset — `"performance"` vs `"stability"`** (also `DOWNDRAFT_GPU_MODE`) — the coarse per-app graphics knob. `"performance"` (games) is hardware-only: no software failover, no GL retry — the boot fails rather than silently degrade. `"stability"` (desktop apps) runs the graceful degradation chain — primary backend (vulkan) → GL backend (virgl; a second wgpu instance whose win repoints `navigator.gpu`/`__wgpuInstancePtr` and rebinds the window's instance-scoped surface via `NativeWindow.recreateGpuSurface`) → software adapter. Granular fields set beside a mode override its individual pieces.
- **Env overrides** — `DOWNDRAFT_GPU=swiftshader|hardware|auto` (existing var, now feeds the policy), `DOWNDRAFT_GPU_BACKEND`, `DOWNDRAFT_GPU_FALLBACK=0|1`, `DOWNDRAFT_GPU_DENY=a,b`.
- **Hardware-boot crash sentinel** — `<userData>/gpu/hardware-boot.pending` is armed before every hardware adapter attempt and disarmed on the first presented frame or clean exit; a stale sentinel on the next boot counts a hardware-boot death, and `CRASH_LATCH_THRESHOLD` (2) consecutive deaths write `latchedAdapter: "software"` into `gpu-state.json` so crashy drivers stop being retried. Explicit hardware/software choices override the latch; a proven-healthy hardware boot clears it.
- **Crash-latch self-recovery** — the latch is no longer permanent under `adapter:"auto"` (a user who fixes a broken driver shouldn't stay on software forever). The driver stack identity is persisted before every `requestDevice` and snapshotted into the latch; each latched boot runs a probe (`requestAdapter` + info query — the last safe interception point) and retries hardware when the identity differs from the stack that crashed (driver updated/reinstalled), or unconditionally once the probation window elapses (`latchRetryMs`, starting at `LATCH_RETRY_BASE_MS` 24h and doubling per failed retry up to `LATCH_RETRY_MAX_MS` 7d). A `probe-boot.pending` sentinel covers a driver corrupted enough to die inside `requestAdapter` itself: it sets `probeDead`, so latched boots skip the probe and only retry blind on the probation schedule — a poisoned stack can't turn the app into a crash-every-boot loop.
- **New wgpu shim exports** (additive — no ABI bump): `wgpu_shim_create_instance_ex(backend_id)` restricts the instance to one backend (`DOWNDRAFT_GPU_BACKEND`/`gpu.backend`), `wgpu_shim_request_adapter_ex` + `wgpu_shim_request_adapter_async_ex` take a per-request `force_fallback` flag (runtime `process.env` mutation doesn't reach the native library's libc environ, so fallback can't be toggled mid-process via env). `wgpu_shim_surface_pick_format` now falls back to the first requested candidate when a surface reports empty capabilities (GLES probing).
- **Desktop window model — `AppWindow`** (`platform-native/src/window/app-window.ts`) — the app-facing window abstraction over `NativeWindow`: `AppWindow.primary()`/`list()`/`create(opts)` unify the primary window (handle 0) and secondary windows (1+), with `setTitle/setSize/setPos/minimize/maximize/restore/setVisible/focus/requestAttention/setDecorations/setAlwaysOnTop/setResizable/setFullscreen/setMinSize/setMaxSize/getTheme/onOccluded/onThemeChanged/onCloseRequest/close`. The static `NativeWindow.byHandle` registry lets shared-queue events route to the owning instance.
- **Primary-window create options** — `NativeWindowConfig` now takes `x`/`y`/`resizable`/`decorations`/`transparent`/`alwaysOnTop`/`skipTaskbar`/`hidden`/`minWidth`/`minHeight`/`maxWidth`/`maxHeight` on the primary window too, applied via the pending-options `dd_window_set_create_options` export (same pattern as `dd_window_set_app_name`). Absent on older libs → the legacy hardcoded defaults (resizable+decorated+visible, WM-placed) reproduce exactly.
- **Handle-addressed window runtime controls** — the `dd_window_secondary_*` FFI family now resolves handle 0 to the primary window, so `NativeWindow`/`AppWindow` runtime controls work uniformly on every window. New optional exports (lazy-probed `winDesktop` group — no ABI bump): `dd_window_secondary_set_minimized`, `set_maximized`, `is_maximized`, `set_resizable`, `set_min_size`, `set_max_size`, `request_attention`, `get_theme`, `set_close_intercept` (existing `set_visible`/`set_decorations`/`set_level`/`set_title`/`focus`/`set_fullscreen` were already handle-addressed).
- **Vetoable close + close policy** — `window.setCloseIntercept(true)` changes the OS close-request path: instead of the immediate hide-then-Quit/WindowClose, an armed window emits `DD_EVENT_CLOSE_REQUEST` (=21) and stays mapped while JS dispatches a cancelable `"closerequest"` event. `preventDefault()` vetoes; an unvetoed request consults `window.closePolicy` — `"lastWindow"` (default) proceeds exactly as the unarmed path (primary quits, secondary destroys), `"explicit"` hides the window instead so tray/background apps stay alive until `downdraft.quit()`. `RunNativeAppModuleOptions` exposes `closePolicy` + a convenience `onCloseRequest` callback (sync or async — `false`/throw vetoes).
- **New window events** — `DD_EVENT_OCCLUDED` (=22, `winit WindowEvent::Occluded` — Wayland/macOS/Android report; damage-gated renderers can park the frame loop on it) and `DD_EVENT_THEME_CHANGED` (=23), dispatched as `"occluded"`/`"themechanged"`; `window.getTheme()`/`AppWindow.getTheme()` query the current light/dark state.
- **IME wiring for html-ui** — editable-element focus (`<input>`/`<textarea>`) now arms the platform text-input path (`startTextInput`) and anchors the IME candidate window at the element's physical-px rect (`setTextInputRect`); editable focus leaving every panel disarms. Composition text arrives via the existing `Ime::Commit → TEXTINPUT` path — preedit stays unwired (the Blitz backend has no marked-text rendering).
- **Maximized state in window-state persistence** — `window-state.json` now records `maximized`; while maximized only the flag flips (normal-mode bounds are never overwritten by monitor-sized bounds), and restore re-maximizes after the saved bounds land so unmaximize returns to the remembered size/position.
- **Native dialogs + notifications** (optional FFI group `winDialogs`, lazy-probed — no ABI bump) — `dd_dialog_open`/`dd_dialog_save`/`dd_dialog_pick_folder` spawn detached `rfd::FileDialog` pickers so the modal never blocks the JS thread or event pump; completion arrives as `DD_EVENT_DIALOG_RESULT` (=24, slot0=req_id, slot1=kind 0 cancel / 1 ok / 2 error) and the NUL-joined path list is pulled with `dd_dialog_result_paths` (snprintf semantics — size call doesn't consume, the copying pull does). `dd_message_box(opts_json)` runs a synchronous modal with `title`/`message`/`level`/`buttons` (ok, okcancel, yesno, yesnocancel) and returns the pressed index; `dd_notify(opts_json)` posts an OS notification via `notify-rust`. `DD_DIALOGS_MOCK=1` resolves every picker with `DD_DIALOGS_MOCK_PATH` (message boxes → 0, notify → success) — short-circuited in both Rust and the JS helper, since the Rust event queue is gated on a live window and the mock exists for windowless/headless runs.
- **`HostAPI` dialogs/notifications/theme** — `downdraft.showOpenDialog`/`showSaveDialog`/`pickFolder` (→ `Promise<string[]|null>`, null = cancel/error), `showMessageBox` (→ pressed index), `notify` (→ bool), `getTheme()`, and `onThemeChanged(cb)` — backed by `createNativeDialogs` (`platform-native/src/bridge/dialogs.ts`), which resolves cleanly to null/0/false when the cdylib predates the symbols.
- **`native-fs-bridge` prefers native dialogs** — the `downdraft.mv` file pickers now use the `dd_dialog_*` group when present and only fall back to zenity/kdialog on older libraries (or when `dialogTool` is set explicitly).
- **Application menus** (optional FFI group `winMenu`, lazy-probed — no ABI bump) — `dd_menu_set(model_json)` installs a real OS menu via `muda` (Windows `HMENU` through `init_for_hwnd`, macOS `NSMenu` through `init_for_nsapp`); `dd_menu_remove` detaches it. Activations arrive as `DD_EVENT_MENU_ACTION` (=25) and the item id is pulled one-per-event with `dd_menu_next_action` (snprintf semantics — the sizing peek doesn't consume). `dd_menu_set_item_enabled`/`dd_menu_set_item_checked` mutate item state by id; `dd_menu_popup(x, y, model_json)` shows a context menu on the primary window. Menu objects live in `thread_local`s on the JS thread — required anyway since muda menus are `Rc`-bound (and macOS only permits menu ops on the app/main thread, which the JS thread is there). On Linux/Android every entry point returns 0 (muda's GTK backend needs a `gtk::Window` our winit surface isn't) → the JS side maps that to the in-window fallback.
- **`HostAPI` menu surface** — `downdraft.setMenu(model)` → `"native" | "inwindow" | "unavailable"` (the return tells the app whether to render the kit `MenuBar` itself), `setMenuItemEnabled`/`setMenuItemChecked`, `showContextMenu(x, y, model)`, and `onMenuAction(cb)` — backed by `createNativeMenus` (`platform-native/src/bridge/menus.ts`). The model is the neutral `AppMenuModel`/`AppMenuItem` union (`shared/types.ts`): `item`/`check`/`separator`/`predefined`/`submenu` with muda-syntax accelerators (`"CmdOrCtrl+O"`). `DD_MENU=inwindow` forces the fallback for kit-bar testing.
- **html-ui-kit in-window menu fallback** (`libraries/html-ui-kit/src/menus.ts`) — `menuBar(model)` renders the model as a strip + dropdowns, `popupMenu(model)` is the context-menu surface, and `menuAccelerators`/`parseAccelerator`/`matchAccelerator`/`acceleratorText` parse `"CmdOrCtrl+O"`-style chords for the app's global key path. New `bindKit` verbs: `kit:menuopen` (label toggle, single-open enforced), `kit:menuitem` (fires `onAction("menuitem", {mid})` with the item's id, auto-toggles check marks, swallows disabled clicks, closes on pick), `kit:menudismiss` (backdrop close). Menu open state lives in `data-open` attrs — every open/close is a doc mutation, so damage-only rendering marks the frame on its own.
- **System tray** (optional FFI group `winTray`, lazy-probed — no ABI bump) — `dd_tray_create(opts_json)` installs one process-wide tray icon via `tray-icon` (`icon` path, `title`, `tooltip`, `menu`, `menuOnLeftClick`); `dd_tray_set_icon`/`set_tooltip`/`set_menu`/`dd_tray_destroy` mutate it. Pointer events arrive as `DD_EVENT_TRAY_EVENT` (=26 — kind click/double-click/enter/move/leave, button, pressed, screen position); tray menu activations ride the same `DD_EVENT_MENU_ACTION` queue with ids namespaced `"tray:<id>"`. Windows/macOS use the native backends; Linux uses tray-icon's `ksni` backend — a pure-DBus `StatusNotifierItem`, so **no GTK/libappindicator runtime dependency** (a session without an SNI watcher just fails `create` → `downdraft.tray.create` returns false). Android reports unavailable throughout.
- **`HostAPI` tray surface — `downdraft.tray`** — `create(opts)`/`setIcon`/`setTooltip`/`setMenu`/`destroy`, `onEvent(cb)` for pointer events, and `onAction(cb)` which filters the `onMenuAction` channel to `tray:`-namespaced ids and strips the prefix.
- **Second-instance forwarding** — a refused `acquireSingleInstanceLock` now pushes `{argv, cwd}` to the primary instance instead of exiting silently: unix socket `<userData>/instance.sock` on POSIX, named pipe `\\.\pipe\downdraft-<appId>` on Windows (500ms bounded — a wedged primary can't hang the exiting newcomer; a failed hand-off reverts to the old silent exit). The primary listens only while it holds the lock; payloads dispatch via `downdraft.onSecondInstance(cb)` — messages that arrive before the bridge subscribes queue and replay to the first listener. Default behavior raises + focuses the primary window (`runNativeAppModule({ focusOnSecondInstance: false })` opts out). `acquireSingleInstanceLock` is now `async` at both call sites.
- **`downdraft.paths`** — per-app platform directories `{ configDir, dataDir, cacheDir }` via new `resolveAppDirs()`: XDG split on Linux (`~/.config`, `~/.local/share`, `~/.cache`), `%APPDATA%`/`%LOCALAPPDATA%` on Windows, `~/Library/Application Support` + `~/Library/Caches` on macOS. The legacy `resolveNativeUserDataDir`/`DOWNDRAFT_USER_DATA` dir is `configDir`.
- **`downdraft.settings`** — typed key/value store persisted to `<configDir>/settings.json` (`{ schemaVersion: 1, values: {...} }`): `get(key, fallback)`, `set(key, value)` (`undefined` removes the key), `getAll()`, `watch(key, cb)` for same-process changes, `flush()`. Writes are debounced ~200ms and atomic (tmp + rename); a corrupt file degrades to an empty store instead of crashing.
- **`draft new --template app`** — desktop-app scaffold: `src/app-module.ts` with a `damageOnly` 2D renderer (zero viewports, explicit clear color), one fullscreen `fit:true` html-ui document on `html-ui-kit` (kit `menuBar` rendered when `setMenu` reports `"inwindow"`), settings/dialog/notification/menu demos, a commented tray block, and `downdraft.config.json` with `native.appId` + `gpu.mode: "stability"`. `src/native-entry.ts` documents `closePolicy`, the `onCloseRequest` veto pattern, and `focusOnSecondInstance`.

### Changed

- **`focused` default in `runNativeAppModule`** — the window now requests activation on launch for packaged apps (`isPackaged()`); `draft dev` still maps inactive so dev-shell restarts never steal focus. Explicit `focused:` overrides either way.

- **`DOWNDRAFT_GPU=auto` is the default adapter mode** — hardware-first with automatic software failover; `draft test`'s `--renderer=cpu|gpu` mapping is unchanged.
- **`backend:"gl"` (virgl GLES) presents on Wayland — experimental** — the event loop's `OwnedDisplayHandle` is now bound to `InstanceDescriptor.display` when GL is requested (required for wgpu's EGL/Wayland presentation), the surface configure path clamps requested usages to real caps, and `viewFormats` are dropped with format-mismatched views coerced to the base format (GLES lacks `VIEW_FORMATS` downlevel flags). Caveats: srgb view reinterpretation degrades to a gamma shift, `captureScreenshot` is unavailable (GLES surfaces expose no `COPY_SRC`), and GLES feature coverage is narrower than Vulkan. Opt-in via `gpu.backend:"gl"`/`DOWNDRAFT_GPU_BACKEND=gl`; the auto backend set is unchanged.

### Fixed

- **Foreign/corrupt pipeline-cache seed no longer bricks rendering** — `wgpu_shim_pipeline_cache_init` now wraps `create_pipeline_cache` in a validation scope: a rejected seed (e.g. a blob flushed by a different adapter — test runners on the software adapter share `<userData>` with hardware boots) is retried with no data so the device gets a live empty cache instead of attaching the invalid one (which previously made every `create_render_pipeline` return an invalid pipeline → per-frame `set_pipeline` validation flood). New return `2` = seed rejected/fresh cache attached; `pipeline-cache.ts` deletes the stale `gpu-pipeline-cache.bin` on `2` so the next boot skips the failed-validation round-trip. `0`/`1` semantics unchanged — no ABI bump.

## [0.5.0](https://github.com/knackstedt/downdraft/compare/v0.4.9...v0.5.0) (2026-10-15)

### Breaking

- **Native FFI symbols renamed** — the stale `sdl_shim_*` exports (winit-backed, not SDL) are now `dd_window_*`/`dd_hotkey_*`; `sdl-ffi.ts` → `window-ffi.ts`. All native cdylibs export `dd_abi_version`, asserted at library load — a stale `.so` now fails loudly with an ABI-mismatch error instead of blank windows. Prebuilt binaries and the TS FFI layer must be updated together.
- **Global bridge renamed** — `window.downdraft` → `globalThis.downdraft`; `__sceneInspector` → `__downdraftDevtools` (native has no `window`).
- **App entry moved** — `app/src/renderer` → `app/src/main`; published path `@downdraft/engine/app/renderer` → `@downdraft/engine/app/main`.
- **Deprecated CLI commands removed** — `draft build`, `dist`, `export`, `mobile`, `build-games` are gone; use `draft release` (`--stage=build|package|release`, `--target=win|linux|mac|android`).
- **Persistence API renamed** — `OpfsSaveStore` → `DirectorySaveStore` (browser OPFS or native filesystem-backed directory handle); `SaveWorkerProxy`, `persistence/browser` subpath, and the `"inline"` save mode removed. Save modes are now `"host"` (typed `ISaveStore` on the main thread) / `"worker"` (sim-worker-owned store) / `"auto"`.
- **`EMBER_LOG_LEVEL`** → `DOWNDRAFT_LOG_LEVEL`.
- **`DOWNDRAFT_STRICT` split** — CLI unknown-flag strictness is `DOWNDRAFT_CLI_STRICT`; engine diagnostics (module DI + WGSL validation) use `DOWNDRAFT_STRICT_DIAGNOSTICS`.
- **`xxh3-ts` tsconfig/deno `paths` alias removed** — it resolved to a `.d.ts` (empty module under tsx/Deno); hashing now loads the real package via a non-aliased seam.

### Security

- **MCP HTTP transport requires the bearer token by default**, including on loopback (the endpoint exposes input injection, state writes, and a REPL). Opt out explicitly with `mcp.requireAuth: false` or `MCP_AUTH=0`. Clients discover the token via the mode-0600 `~/.downdraft/port/<pid>.token` file.
- **`postinstall` native fetch verifies SHA-256** — `fetch-native.mjs` checks each `downdraft-native-*.tar.gz` against the `.sha256` published by `native.yml`; mismatch aborts the install.
- **Docs no longer call `worker-js` plugins "sandboxed"** — wasm/quickjs are hard-isolated; worker-js runs with host-runtime privileges (capability-restricted, not a security boundary).

### Added

- `CONTRIBUTING.md`, `SECURITY.md`, `CODE_OF_CONDUCT.md`, `THIRD_PARTY_NOTICES.md`, `deny.toml`.
- `docs/adr/` — ADRs for the native runtime, the Vite dev shell, and the tri-runtime JS host.
- `docs/site` architecture section gains module-system, native-platform, android, engine-internals, plugin-internals, profiling, devtools, and gaussian-splats pages (content moved out of `AGENTS.md`); `reference/testing.md` + `reference/limitations.md` document the automation harness and known gaps.
- `DOWNDRAFT_GPU=swiftshader` now actually forces wgpu's software/fallback adapter at the Rust `request_adapter` boundary (previously documented but unconsumed in-process).
- `draft test --app=packaging-smoke` / `tests/e2e/packaging-smoke-smoke.spec.ts` — a self-contained e2e path that needs no `games/` clone; `resolveAppDir` also resolves `examples/<name>`.
- CI: cross-platform smoke job (Windows/macOS) for the pure-TS surface, `cargo-deny` licenses+advisories gate, npm license check, sha256 checksum publication + verification in `publish.yml`.

## [0.3.0](https://github.com/knackstedt/downdraft/compare/v0.2.0...v0.3.0) (2026-10-10)
