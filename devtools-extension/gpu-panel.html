GPU Diagnostics

GPU System Metrics (MCP: gpu_system_info)
Real-time GPU utilization %, VRAM usage, temperature, power draw, clock speeds, and per-process VRAM — all available to AI agents via the gpu_system_info MCP tool or downdraft://gpu-info resource. No external terminal needed.
MCP tool: gpu_system_info
Electron GPU Info (MCP: inspect_gpu)
Driver version, vendor, GPU device, active feature status — retrieved via Electron's app.getGPUInfo() and available through the inspect_gpu MCP tool. Replaces the need for chrome://gpu.
MCP tool: inspect_gpu
VRAM Resource Tracking (in-engine)
Per-buffer and per-texture VRAM allocation with callsite tracking — shown in the GPU Resources table above. More granular than per-process nvidia-smi. Use getGPUResourceStats via SceneInspector API.
SceneInspector: getGPUResourceStats

External Tools (interactive, not automatable)

nvtop (htop-style GPU view)
Live htop-style view of GPU processes. Easier to correlate spikes with what you're doing in-app.
nvtop
Vulkan Validation Layer
Flags redundant barriers, suboptimal memory types, and other things that silently cost GPU time. Set as env var before launching the app.
VK_LAYER_KHRONOS_validation=1
chrome://tracing
Chromium compositor/GPU-process behavior specific to the Electron-style host. Catches sync stalls or redundant work from multi-process model.
chrome://tracing
RenderDoc (Vulkan frame capture)
Since Dawn renders via Vulkan on Linux, RenderDoc captures individual frames from the Vulkan backend. Fastest path to "why is this draw call expensive" — pipeline state, texture sizes, redundant passes, overdraw all show up per-frame.
Launch RenderDoc, then inject into the Electron renderer process
NVIDIA Nsight Graphics
Deeper GPU-side metrics (SM occupancy, memory bandwidth, shader stalls) than RenderDoc. Worth it once RenderDoc tells you which pass is the problem and you need to know why at the hardware level.
Launch Nsight Graphics, connect to the Vulkan process
NVIDIA Nsight Systems
Timeline view across CPU and GPU. Useful for spotting sync stalls or redundant work caused by Electron's multi-process model (e.g. compositor process doing unexpected work).
nsys profile <your-app-launch-command>
